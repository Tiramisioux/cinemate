# C9 results — shipped 2026-09-02, with a mid-flight design reversal

`PLAN.md`, `GATES.md`, `SONNET-PROMPT.md` and `SONNET-PROMPT-PANE.md` (this directory) are
the plan as it stood 2026-09-01: thumbnail-first, with the raw decoder kept as the fallback
for footage shot before the change, twelve gates across five sessions. They were never
merged to `dev` — [PR #181](https://github.com/Tiramisioux/cinemate/pull/181)
(`feature/c9-clip-playback-plan`) sat open while implementation ran on different branches
entirely; its four files are brought into this directory now, unedited, as the historical
record of what was decided before any code was written. **This file is what actually
shipped, and how far it diverged from that plan.**

This is a real gap, not a paperwork one: the cinemate side that shipped assumes a cinepi-raw
build that writes the thumbnail (`thumbnail_startup_value()` defaults to 2 — colour), and
that cinepi-raw code is hardware-verified (see G10/G11 below) but **not yet on cinepi-raw's
own `dev`**. A Pi running stock cinepi-raw `dev` alongside this cinemate `dev` will record
takes with no embedded thumbnail, which the shipped Playback pane cannot play back at all
(see "raw decode is disabled," below) — it needs cinepi-raw PR #71 merged and built first.

## The reversal: thumbnail-first-with-fallback → thumbnail-only

The plan's core mechanism — decode the raw image when no thumbnail is present — was built,
matches `GATES.md`'s G1/G2, and passed desk verification. It shipped **disabled**. After
Phase 0 landed and was hardware-tested, the operator's own words:

> "works now. but i think the implementation here is a bit too complicated. have thumbnail
> as standard. raw is too demanding on the system i think so leave it out (but keep the code
> as we might revisit this later)."

`src/module/app/playback.py`'s `_RAW_DECODE_FALLBACK_ENABLED = False` is the entire
re-enable switch — `decode_frame()`, the demosaic path, `_load_rows()`'s 10-bit unpack are
all still present and desk-verified, just unreachable from `frame_jpeg()` while the flag is
off. A take recorded with the thumbnail toggle off, or on a pre-Phase-0 cinepi-raw build,
currently **cannot be played back at all** — this is a deliberate consequence of the
reversal, not an oversight (see `docs/playback.md`'s "Source" section). The same session
flagged a possible future use for the thumbnail plane beyond playback: "this thumbnail thing
could be a nice way to get proxy files in the future" — not built, recorded here as intent
only.

## Everything else that changed after the plan was written

None of the following are in `PLAN.md` — they were operator steers made against the running
pane on real hardware, applied in the same session:

- **Clip order reversed.** `playback.list_clips()` now sorts oldest-first (shooting order,
  first take upper-left) instead of newest-first; `raw_files.list_takes()` itself is
  untouched (the RAW files pane still wants newest-first for quick access/deletion) — the
  re-sort is scoped to the Playback pane's own take strip.
- **The DROP badge changed what it measures.** It used to report *this playback session's*
  render speed; `playback.dropped_frame_count()` now reads gaps in the *recording's own*
  frame-index filenames instead — a property of the take, not of how well this browser tab
  kept up.
- **LOG10 badge, new.** `dng_preview.describe_mode()` infers it from `BitsPerSample`==10 plus
  a `LinearizationTable` — unambiguous, unlike the existing `HDR`/`CRV` badges (12-bit +
  table is ambiguous between ClearHDR companding and CineMate Log; 10-bit + table is not,
  nothing else produces that combination).
- **Preview-scale control and monochrome-sensor switch removed** from the Playback pane
  entirely — the thumbnail is a fixed size, so there was nothing left for either control to
  do.
- **Settings-editor tab order fixed:** config.txt, settings.jsonc, Live view, Playback,
  RAW files. Several page intro paragraphs and the "DNG thumbnail" settings card removed as
  confusing (the card's underlying `image_capture.thumbnail` setting is kept as a hidden
  `data-path` passthrough — deleting the field outright would have reintroduced the exact
  `buildState()`-drops-unrepresented-keys bug an earlier review round had already fixed).
- **New feature, not in the plan at all:** a per-clip scrub-thumbnail with quick preview on
  the RAW files pane, `wireClipThumb()`/`pbJumpToTake()` — clicking a clip's thumbnail jumps
  to the same take on the real Playback pane. Its layout was iterated three times against
  operator feedback in one session (between checkbox and name → after the name filling to
  the size column → back between checkbox and name, height/width tuned to align with the
  name/badges text block) before landing.
- **Explicitly declined:** download and delete controls on the Playback pane (RAW files pane
  keeps its own).

## Gates: two of twelve actually ran

`GATES.md` defines G0–G11 across five sessions, most of them built around the raw-decode
mechanism the pane shipped with disabled. Only **G10/G11** — does the thumbnail actually
land in the DNG, and what does writing it cost on the Pi — were the ones the shipped feature
depends on, and the only ones reported: hardware-confirmed working ("works now"), which is
what triggered the reversal above. G1–G9 test a code path (`decode_frame()`/raw fallback)
that is built, desk-verified, and currently unreachable; they were not run in their original
form and are moot unless the fallback is re-enabled. G12 (the pane session's own closing
gate) likewise never ran as specified — the pane's actual acceptance was the same live
hardware session that produced the reversal above, not a separate scripted gate.

## Merging into `dev`: a real conflict, not a formality

`dev` had moved substantially since this branch was cut — [PR #184](https://github.com/Tiramisioux/cinemate/pull/184)
("web-ui-combined") touched the same core files. Reconciling required manual resolution in
`src/main.py`, `src/module/config_loader.py`, `src/module/app/raw_files.py` (both sides
independently extended `delete_take()` — dev's `active_take_names()` + `delete_take(name, *,
storage=None)` is a strict superset, kept, alongside this branch's own `safe_take_children()`)
and `src/module/app/templates/settings_editor.html` (dev's new hash-based page routing
against this branch's Live-tab iframe lifecycle — both kept, merged into one `setActivePage`).
Two defects were caught only by this reconciliation, not by either branch's own review:

- dev's `PAGE_LANDING` table (which URL hash each tab lands on) had no entry for this
  branch's new `playback` page — every visit to the Playback tab would have pushed
  `#undefined` into the URL. Fixed by adding `playback: 'playback'` and confirming a
  `#playback` deep link lands correctly, post-merge.
- `settings_editor.py`'s `flask` import block auto-merged **without a conflict marker** but
  silently dropped `send_file` (still needed by `get_playback_audio()`) while correctly
  dropping `after_this_request` (the route it served was genuinely superseded by dev's new
  streaming download implementation). Caught by `ruff check src/`'s `F821`, not by the merge
  itself — a reminder that a clean auto-merge is not proof of a correct one.

Full gate suite re-run green after resolution (905 passed / 405 subtests, up from 742 —
dev's own new tests included); a manual JS smoke test of the merged `setActivePage`/
`pageFromHash`/`syncLiveEmbed` logic and the RAW-files thumbnail feature against a local
Flask instance before pushing. `feature/dng-playback` was kept (not deleted) after the merge,
per operator instruction, and fast-forwarded to match `dev` exactly so a future PR from it
starts with nothing to reconcile.

## Still open

- **The thumbnail writer works; it is simply not merged.** Confirmed on hardware by the
  operator 2026-09-03, consistent with G10/G11 below — the pane plays back from the embedded
  thumbnail on the rig, which closes the functional question this step opened. What remains
  is landing cinepi-raw PR #71: the writer still exists only on a feature branch, so
  cinemate's shipped default (`thumbnail: 2`) is inert on a Pi running stock cinepi-raw
  `dev`, and such a Pi records takes the Playback pane cannot open. A merge task, not a
  defect.
- **The raw-decode fallback is built but off**, and effectively unverified against the
  current pane (its own gates, G1–G9, never ran against the shipped code path). Re-enabling
  it later means re-running those gates for real, not assuming they still hold.
- **Gates G0, G3–G9, G12** as specified in `GATES.md` never ran, for the reasons above — this
  is not an oversight to chase, since the mechanism most of them cover is currently disabled,
  but it should not be read as "gated and passed."
