# Settings editor — implementation plan

## Goal

Turn the static mockup (`concept.html`) into a real 4-pane page served by
Cinemate's existing Flask app: config.txt | settings.jsonc | RAW files | Live
view. No new process, no new port — a new blueprint registered in the same
`create_app()` that already serves the live-camera page at `/`.

## Verified starting state (2026-08-17, after merging origin/dev)

- **F1** — Flask app is a factory (`src/module/app/__init__.py:6-53`,
  `create_app(redis_controller, cinepi_controller, simple_gui, sensor_detect,
  command_executor, settings)` → `(app, socketio)`), started once from
  `src/main.py:917-926` as a background thread inside the single `main.py`
  process (`0.0.0.0:5000`, Werkzeug dev server, `threading` async mode). A new
  blueprint is purely `app.register_blueprint(...)` in `__init__.py` — no
  process/service boundary to cross.
- **F2** — Shared state (`redis_controller`, `cinepi_controller`,
  `sensor_detect`, `command_executor`, `settings`) is stashed on
  `app.config[...]` at construction time; any new blueprint reads it via
  `current_app.config[...]`.
- **F3** — `/api/v1/cmd`, `/api/v1/status`, `/api/v1/commands`
  (`src/module/app/api.py`) already exist and are the intended reuse surface:
  `/cmd` dispatches any `CommandExecutor` command line (same table the CLI and
  serial paths use), `/status` returns every `ParameterKey` from Redis,
  `/commands` introspects the CLI command table. `dev_projects/web-api/
  IMPLEMENTATION-PLAN.md`'s own "explicitly do not" list says: don't add
  per-parameter endpoints, the command string is the API. Follow that
  precedent here too.
- **F4** — Cinemate's live-camera page already exists at `/`
  (`src/module/app/main/routes.py`, `templates/template.html`, driven by
  `/api/v1/cmd`) — this is functionally the mockup's "Live view" pane. Do
  **not** rebuild it; the settings editor's Live view tab iframes it.
- **F5** — settings.jsonc is **read-once-at-startup, no write-back path
  anywhere** (`src/module/config_loader.py`). Reusable: `strip_jsonc()`
  (`config_loader.py:487-494`, hand-rolled comment/trailing-comma stripper,
  not a library) and `_apply_settings_defaults()`
  (`config_loader.py:149-383`, idempotent — safe to run over a saved file to
  sanity-check it). The write itself is new.
- **F6** — Every settings.jsonc caller hardcodes the absolute path
  `/home/pi/cinemate/settings.jsonc` (`src/main.py:51`,
  `cinepi_multi.py:27`, `cinepi_controller.py:27`, `wifi_hotspot.py:37`). The
  editor's write path must target the same path — this is a live-hardware
  constant, not configurable.
- **F7** — `hardware_controls.*` and `input_peripherals.quad_rotary_controller`
  method fields (`{"method": "<name>", "args": [...]}`) are resolved via
  **bare `getattr()` on `cinepi_controller`**
  (`src/module/gpio_input.py:466-477`, `src/module/i2c/
  quad_rotary_controller.py:113-122`) — a **different namespace** from
  `cli_commands.py`'s CLI-string table (`'set resolution'` vs
  `set_resolution`). The mockup's `ACTION_METHODS` list (`concept.html:2958-
  2971`) has 3 entries that fail this lookup at runtime: `erase` → must be
  `erase_drive`, `format` → must be `format_drive`, `storage_preroll` isn't a
  `cinepi_controller` method at all (it's `storage_preroll.trigger_manual`,
  CLI/serial/web-API-only) and must be dropped from the GPIO/quad-rotary
  catalog. Fix this when porting the action picker.
- **F8** — Restart: `cinepi_controller.restart_cinemate()`
  (`cinepi_controller.py:2255-2259`) does `os.execl` self-re-exec (same PID,
  systemd's `Type=notify` unit keeps tracking it). Reachable today with zero
  new plumbing via `POST /api/v1/cmd` body `restart cinemate` — confirmed
  **not** in `DESTRUCTIVE_COMMANDS` (`api.py:31`), so it's already the safe,
  established trigger. The save flow calls this in-process directly
  (`current_app.config['CINEPI_CONTROLLER'].restart_cinemate()`), no HTTP
  round-trip needed.
- **F9** — config.txt has **zero Python plumbing** (grep confirmed). The
  managed block is fenced by `# >>> cinemate-install >>>` /
  `# <<< cinemate-install <<<` (`cinemate-install.sh:112-113`), generated by
  the Python heredoc at `cinemate-install.sh:984-1134` — per-sensor
  `camera_section()` blocks (imx477/imx296/imx283/imx585/imx585_mono, only
  the active one's `camera_auto_detect=`/`dtoverlay=` lines uncommented),
  `dtparam=i2c_arm/i2s/spi/audio`, an optional RP1-overclock block
  (`#dtoverlay=rp1-overclock`, Pi 5 only), `[cm4]`/`[cm5]`/`[all]` sections.
  The install script's own update-in-place path
  (`cinemate-install.sh:1540-1550`) deletes the fenced region with `sed` and
  re-appends a fresh one — same pattern the editor's write path should use
  (never touch anything outside the fence).
- **F10** — RAW takes live under `/media/RAW` (active) plus `/media/RAW1`,
  `/media/RAW2`, … (standby, promoted on active-drive removal) — convention
  owned by `services/storage-automount/storage-automount.py`. Only a
  "most-recent take" scanner exists (`SSDMonitor.get_latest_recording_infos()`,
  `src/module/ssd_monitor.py`); no list-all/delete/download anywhere. Take
  dirs contain `.dng` (`CINEPI_<yy-mm-dd>_<hhmmss>_F<fps>_C<take#>_
  <frame idx>.dng`) and optionally `.wav`.
- **F11** — 22 real tuning files in `resources/tuning_files/` (mockup's count
  is accurate). No upload endpoint exists.
- **F12** — the mockup has **zero backend integration** (no fetch/
  localStorage/WebSocket anywhere) — every pane's interactions are faked with
  `setTimeout`/DOM mutation. Nothing partial to build on; every pane needs a
  real endpoint end-to-end.

## Architecture

One new blueprint, `settings_editor_bp` (`src/module/app/settings_editor.py`,
`url_prefix='/settings-editor'`), registered in `create_app()` next to
`main_routes`/`api_v1`. One new template,
`src/module/app/templates/settings_editor.html`, porting the mockup's DIN2014
HUD CSS/nav shell but replacing every faked interaction with a real `fetch()`
call. Reuses the existing `static/DIN2014-{Bold,Regular}.ttf` and
`static/js/socket.io.min.js`.

Endpoints (all under `/settings-editor/api/`):

| Method | Path | Does |
|---|---|---|
| GET | `/settings` | Parse settings.jsonc (`strip_jsonc`+`json.loads`), return as JSON |
| PUT | `/settings` | Validate shape, atomic write (`temp file + os.replace`) to `/home/pi/cinemate/settings.jsonc`, then `cinepi_controller.restart_cinemate()` |
| GET | `/actions` | Introspect `cinepi_controller` public callables (getattr-safe, matching F7) for the button/switch/quad-rotary method picker |
| GET | `/config-txt` | Parse the fenced managed block from `/boot/firmware/config.txt` into the same shape `camera_section()` generates |
| PUT | `/config-txt` | Regenerate the fenced block (port `cinemate-install.sh`'s generator), `sudo reboot` |
| GET | `/raw/takes` | List every take dir under `/media/RAW*` with metadata |
| DELETE | `/raw/takes/<name>` | Delete one take dir |
| GET | `/raw/takes/<name>/download` | Zip-stream one take |
| POST | `/raw/bulk` | `{"action": "delete"\|"download", "names": [...]}` |
| GET | `/tuning-files` | List `resources/tuning_files/*.json` |
| POST | `/tuning-files` | Upload a new tuning file (multipart) |

Live view pane: `<iframe src="/">` — no new backend.

## Explicitly do not

- Do not rebuild the live-camera page — iframe it (F4).
- Do not add per-parameter settings endpoints — one GET/PUT pair for the
  whole settings.jsonc document (F3 precedent).
- Do not source the GPIO/quad-rotary action picker from `cli_commands.py`'s
  CLI-string table — it's the wrong namespace (F7).
- Do not add schema validation via a new library — reuse
  `_apply_settings_defaults()` (idempotent) as the sanity check (F5).
- Do not touch anything outside the `# >>> cinemate-install >>>` fence in
  config.txt (F9).

## Sequencing

1. Blueprint skeleton + nav shell (empty panes, DIN2014 HUD styling ported).
2. settings.jsonc pane — full read/edit/save/restart (highest-value, most
   fleshed-out in the mockup).
3. config.txt pane — read + write + reboot.
4. RAW files pane — list/delete/download.
5. Live view pane — iframe embed (last, since it's reuse not new build).

## Verification

Each step: `preview_start` the Flask app via `.claude/launch.json`, drive the
new pane through `preview_click`/`preview_fill`/`preview_snapshot`, confirm
the real file (settings.jsonc/config.txt) or `/media/RAW` state actually
changed — not just that the UI reports success. Settings.jsonc and config.txt
writes are safest verified against a scratch copy first, then against the
real Pi over SSH (`pi@cinepi.local`) before calling a pane done.
