# F-003 — `requirements.txt` is decorative; the installer carries its own divergent dep list

- **repo:** install
- **severity:** high
- **confidence:** confirmed
- **category:** install-drift
- **evidence:** `cinemate-install.sh:922-927`, `requirements.txt:1-22`
- **needs-pi:** no
- **effort:** S

## What

`grep -n "requirements" cinemate-install.sh` returns **nothing**. The installer never
reads `requirements.txt`. It pip-installs an inline list inside
`install_python_environment()`:

```
cinemate-install.sh:922    run_as_pi "$pip_cmd" install \
                  923        gpiozero \
                  924        adafruit-blinka adafruit-circuitpython-ssd1306 adafruit-circuitpython-seesaw \
                  925        luma.oled grove.py pigpio-encoder smbus2 rpi_hardware_pwm \
                  926        watchdog psutil pillow redis keyboard pyudev numpy termcolor sounddevice \
                  927        evdev inotify_simple sysv_ipc flask_socketio sugarpie
```

plus a conditional `lgpio` when `INSTALL_ALT_GPIO_BACKEND` is true.

### Divergence, computed

**In the installer, absent from `requirements.txt` (11):**
`luma.oled`, `grove.py`, `pigpio-encoder`, `smbus2`, `rpi_hardware_pwm`, `watchdog`,
`keyboard`, `sounddevice`, `evdev`, `inotify_simple`, `sysv_ipc`

**In `requirements.txt`, absent from the installer (4 runtime + 3 docs):**
`rpi-lgpio`, `flask`, `wave`, `pyaudio` — plus docs-build deps `mkdocs-with-pdf`,
`schemdraw`, `schemdraw-markdown`

This exactly reproduces the count asserted in KICKOFF §6.4.

### `flask` is never installed directly

`flask` appears only in `requirements.txt`, which nothing reads. On a real install it
arrives solely as a transitive dependency of `flask_socketio`. The app imports `flask`
directly in at least four modules (`app/__init__.py`, `app/api.py`, `app/main/routes.py`,
`app/settings_editor.py`), so the runtime depends on a package it never declares to the
installer. It works today only because `flask_socketio` happens to pull it in.

## Why it matters

Two dependency lists that nothing reconciles will keep drifting. The failure mode is
delayed and confusing: a fresh install works, then a `flask_socketio` release drops or
renames its Flask pin and the camera stops booting with an ImportError that points at
CineMate code rather than at the real cause. `requirements.txt` also actively misleads —
a contributor reasonably assumes it is the dependency contract.

## Proposed action

Decide which list is canonical. Two coherent options:

1. **Installer is canonical** (matches current reality): delete `requirements.txt`, or
   reduce it to a pointer comment naming `install_python_environment()`. Split docs-build
   deps into `docs/requirements-docs.txt` used by the `docs.yml` workflow.
2. **`requirements.txt` is canonical**: fix its contents (F-002), add `flask` explicitly,
   and change the installer to `pip install -r requirements.txt`. Keeps the hardware-only
   packages (`grove.py`, `sysv_ipc`, …) out of a Mac dev install only if they are split
   into a second file.

Option 1 is the smaller change and the honest one. Option 2 buys a single source of
truth but needs a `requirements-hardware.txt` split to stay installable off-Pi.

Either way, `flask` must be declared explicitly wherever the canonical list lives.

## Risk if changed

Low for option 1 (deleting a file nothing reads). Medium for option 2 — changing the
installer's pip invocation is a boot-path change and must be validated by a full clean
install on hardware.

## How to verify the fix (Mac / Pi)

- **Mac:** `grep -c requirements cinemate-install.sh` and diff the chosen canonical list
  against the set of top-level imports harvested from `src/`. A small script in
  `harness/` can do this and become a CI check (ties into F-006).
- **Pi:** full clean install on a blank SD card; confirm the venv resolves and CineMate
  reaches camera-ready. Queued as PI-004.
