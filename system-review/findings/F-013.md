# F-013 — `src/stream.py` is a dead second Flask entry point that cannot run

- **repo:** cinemate
- **severity:** medium
- **confidence:** confirmed
- **category:** dead-code
- **evidence:** `src/stream.py:1-21`, `src/module/app/__init__.py:6`, `src/main.py:935`
- **needs-pi:** no
- **effort:** S

## What

`src/stream.py` (21 lines) is a self-contained `if __name__ == '__main__'` entry point
that stands up the Flask/SocketIO app on port 5000. It is broken in three independent
ways, any one of which is fatal:

1. **Unresolvable import.** `src/stream.py:2` is `from app import create_app`. There is
   no top-level `app` module — the package is `module/app`, and every other importer
   spells it `module.app` (see `src/module/app/settings_editor.py`). This raises
   `ModuleNotFoundError` at import time.

2. **Wrong arity.** `src/stream.py:14` calls
   `create_app(redis_controller, cinepi_controller, simple_gui)` with 3 positional args.
   `src/module/app/__init__.py:6` defines
   `def create_app(redis_controller, cinepi_controller, simple_gui, sensor_detect, ...)`
   — at minimum a fourth required parameter, `sensor_detect`.

3. **Bare constructors.** `src/stream.py:9-11` constructs `RedisController()`,
   `CinePiController()` and `SimpleGUI()` with no arguments. The real boot path in
   `src/main.py` wires these with substantial dependencies; the no-arg forms are not how
   the system is assembled.

Nothing references it: grep for `import stream`, `src/stream`, and `stream.py` across
`src/`, `services/` and `cinemate-install.sh` returns no hit. The live server is started
instead at `src/main.py:935`:

```
threading.Thread(target=socketio.run, args=(app,),
                 kwargs={'host': '0.0.0.0', 'port': 5000, 'allow_unsafe_werkzeug': True})
```

## Why it matters

It is a trap for exactly the reader this review is meant to serve. A developer new to the
repo, looking for "where does the web GUI start", finds a 21-line file named `stream.py`
whose whole job appears to be starting the web GUI — and it is a lie. It will cost
someone an hour, and it invites a "fix the import" patch that resurrects a parallel boot
path nobody wants.

It also confirms that the web app once had a standalone launcher and that `main.py`
absorbed it without the old file being removed. That history is worth one line in the
code map (S02).

## Proposed action

Delete `src/stream.py`. There is no salvage case: the only thing it documents is the
`create_app` signature, which the real caller in `src/main.py` documents better.

If the operator wants a standalone "web GUI only, no hardware" dev launcher — which
would be genuinely useful for the S07 harness work — that should be written fresh
against the current `create_app` signature and live in `system-review/harness/`, not
resurrected from this file.

## Risk if changed

None. The file is unreachable and unimportable. Blast radius is zero; rollback is
`git revert`.

## How to verify the fix (Mac / Pi)

- **Mac:** `python3 -c "import ast,sys; ast.parse(open('src/stream.py').read())"` proves
  only that it parses, not that it runs — the failure is at import, not parse time.
  The real check is `grep -rn "stream" --include=*.py --include=*.sh src services
  cinemate-install.sh`, which must stay empty of references after deletion.
- **Pi:** none needed. Deleting an unreferenced, unimportable file cannot change runtime
  behavior.
